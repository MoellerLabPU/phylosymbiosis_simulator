# Phylosymbiosis simulations

This page details a simulation pipeline for comparing distance/dissimilarity-based and tree-based tests of phylosymbiosis. The pipeline runs seven model/reconstruction variants with **Bray–Curtis** and **binary Sørensen–Dice** dissimilarities, producing replicate tables, statistical summaries, and six-panel figures.

Both dissimilarity measures receive terminal abundance noise and taxon replacement noise, with parameters configured separately for each measure.

## Quick start

Use **Python 3.11 or newer**. Download or clone the repository, then open a terminal in the directory containing `run_simulations.py` and `config.json`.

### macOS / Linux

```bash
python3 -m pip install -r requirements.txt
python3 run_simulations.py --jobs 4
```

### Windows

```powershell
py -m pip install -r requirements.txt
py run_simulations.py --jobs 4
```

This runs all seven variants with both dissimilarity measures and generates **14 figures**, each in PDF, PNG, and SVG formats. `--jobs` controls the number of worker processes.

The source package contains code and configuration; full simulation outputs are generated by running the pipeline.

## Configuration

Edit `config.json` to change common defaults, variant overrides, run sizes, or the two measures' terminal noise settings. The default noise configuration is:

```json
"metrics": {
  "BrayCurtis": {
    "tip_abundance_sigma": 1.0,
    "tip_replacement_fraction": 0.66
  },
  "BinaryDice": {
    "tip_abundance_sigma": 1.0,
    "tip_replacement_fraction": 0.66
  }
}
```

`tip_abundance_sigma` is the standard deviation of a zero-mean normal draw on the log abundance scale. Each present taxon's abundance is multiplied by `exp(Normal(0, sigma))`, then the community is normalized. Absent taxa remain absent.

`tip_replacement_fraction` is the expected fraction of present taxa replaced at each host tip. The replacement count is drawn from a binomial distribution and capped by the number of absent taxa. Removed taxa and arrivals are selected uniformly without replacement; arrivals come from taxa absent before replacement. 

**Binary Dice uses presence/absence (`profiles > 0`) without an abundance threshold.** Terminal abundance noise therefore does not change Dice distances when occupancy is unchanged.

### Default run sizes

| Setting | Default |
| --- | --- |
| Alternative replicates per condition | 200 |
| Null replicates per condition | 1,000 |
| Host-label permutations per test | 999 |
| Host tips | 8, 15, 30, 50 |
| Host-tree depth | 6 |

The root community contains 100 taxa from a pool of 1,000, with a community-size cap of 150. The richness suite varies root richness and scales the cap to 1.5 times root richness. 

## Run selected analyses

The following examples use macOS/Linux commands. On Windows, replace `python3` with `py`.

Run one variant and one measure:

```bash
python3 run_simulations.py --variants brownian_0p30 --metrics BrayCurtis --jobs 4
```

Run multiple variants with binary Dice:

```bash
python3 run_simulations.py --variants ou white_noise --metrics BinaryDice --jobs 4
```

Omit `--variants` or `--metrics` to run all choices for that argument. Both accept one or more names.

For a small trial run in a separate output directory:

```bash
python3 run_simulations.py --variants brownian_0p30 --reps 5 --null-reps 10 --permutations 99 --jobs 2 --output-dir trial_run
```

`--null-reps` must exceed `--reps` for the ROC bootstrap. Trial runs check execution; use the full defaults for the configured production analyses.

### Other options

| Option | Purpose |
| --- | --- |
| `--check-only` | Validate noise parameters, host-tree properties, statistical identities, and profile normalization |
| `--no-figures` | Generate simulation tables without drawing figures |
| `--figures-only` | Redraw figures from existing result tables |
| `--output-dir PATH` | Write results and figures to a separate directory |
| `--formats pdf png` | Select figure formats from `pdf`, `png`, and `svg` |
| `--save-trees` | Export one shared host-tree ensemble |

Rerunning an analysis in the same output directory replaces its generated tables and figures. Use a separate `--output-dir` to retain earlier runs.

## Simulation suites and figures

Fresh pure-birth Yule host trees are generated for each host-tip count and replicate.

| Suite | Conditions |
| --- | --- |
| `main` | 8, 15, 30, or 50 hosts; independent-community fractions of 0, 0.25, 0.50, and 0.75 |
| `calibration` | Independently generated communities and host-label-shuffled communities at each host-tip count |
| `richness` | Root richness of 10, 50, 100, or 500 taxa at 15 hosts |
| `uncertainty` | 0, 1, 3, or 6 attempted nearest-neighbor interchange moves at 15 hosts and condition-noise level 0.25 |

Each figure contains:

| Panel | Analysis |
| --- | --- |
| A | Detection rate across root community richness |
| B | False-positive rate under the two null models |
| C | Detection rate across condition-noise levels at 15 hosts |
| D | Detection rate across host-tip counts at condition-noise level 0 |
| E | ROC curves at condition-noise level 0.50 and 15 hosts |
| F | Detection rate under host-topology perturbation |

## Statistical methods

- **Raw Mantel:** correlation between host patristic distances and untransformed community dissimilarities.
- **Reconstructed-distance Mantel:** correlation with dendrogram cophenetic distances, or NJ path lengths for neighbor joining.
- **Normalized Robinson–Foulds (RF):** congruence of nontrivial unrooted splits.
- **Clustering information:** split-based mutual information with optimal assignment.
- **Normalized matching cluster (MC):** optimal assignment of symmetric-difference costs between nontrivial rooted clades.

All methods share the same host-label permutations within a comparison and use the permutation `+1` correction. The primary Mantel tests are positive, one-sided tests (two-sided Mantel p-values are also reported). A rejection is recorded when `p < 0.05`. Detection-rate confidence intervals use Wilson intervals.

MC is divided by the sum of clade sizes across both trees, an upper-bound normalization rather than an exact maximum-distance normalization. For NJ, signed edge estimates are retained for distance tests. MC uses a separate copy with negative edges clipped to zero before midpoint rooting.

## Outputs

Each analysis writes to `results/<variant>/<metric>/` and `figures/<variant>/<metric>/`.

Result files include:

- `{suite}_replicates.tsv` and `{suite}_summary.tsv` for all four suites.
- `run_configuration.json`, recording effective settings, run sizes, seeds, and validation results.
- `roc_auc.tsv` and `roc_curves.tsv`, including AUC estimates and bootstrap confidence intervals.
- `{figure_name}C_plot_data.tsv` and `{figure_name}D_plot_data.tsv`, containing the corresponding panel data.

Every replicate table records both terminal noise parameters. Shared tree diagnostics are written to `results/tree_diagnostics.tsv`. Each analysis produces its assigned `Figure1` or `FigureS1`–`FigureS13` filename in PDF, PNG, and SVG formats unless formats are restricted. The panel-data filenames use the same figure prefix.

To redraw all figures after a run:

```bash
python3 make_figures.py
```

For results written elsewhere:

```bash
python3 make_figures.py --output-dir trial_run --variants brownian_0p30
```

## Reproducibility and verification

The default base seed is `20261005`, with final simulation namespace `9`. Dependency versions are pinned in `requirements.txt`.

Generate the default shared ensemble of 4,000 Newick trees without running the simulation suites:

```bash
python3 run_simulations.py --check-only --save-trees
```

Trees are written to `trees/depth_6/`.

## Repository files

- `run_simulations.py`: command-line runner, Yule trees, noise application, and simulation suites.
- `community_simulator.py`: abundance evolution, extinction, colonization, and tree helpers.
- `simulation_core.py`: distance calculations, reconstruction, permutation statistics, and summaries.
- `make_figures.py` and `plot_utils.py`: figure rendering and ROC/AUC calculations.
- `config.json`: shared settings, separate measure-specific noise controls, and variant overrides.
